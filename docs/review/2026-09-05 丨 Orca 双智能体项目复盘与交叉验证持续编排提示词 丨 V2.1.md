不能只依靠 Orca mailbox / worker_done。


```text

```

每轮监督都同时检查：

### Channel A

Orca lifecycle events。

### Channel B

真实文件工件。

如果事件通道与真实工件出现分叉：

先进行 Completion Reconciliation。

不得无限等待一个已经实际完成的 Worker。

## Source of Truth 必须分层

本任务不得使用一句笼统的“文件就是唯一真相”覆盖所有状态。

### BUSINESS / WORK STATE 的 Source of Truth

优先依据：

- 真实 Markdown Artifact；
- Artifact 内容；
- 文件 mtime；
- Worker 实际输出；
- 必要的项目证据。

### CONTROL-PLANE STATE 的 Source of Truth

优先依据：

- Run；
- Task；
- Dispatch；
- Worker lifecycle；
- Orca completion / settlement 状态。

最终必须通过：

> **Business Truth ↔ Control-plane Truth Reconciliation**

确认二者一致。

文件存在不能自动等于生命周期已经完成；
生命周期显示 completed 也不能自动等于业务 Artifact 已经合格。

# 二十二、L3 外部 watchdog

检查当前项目治理体系是否已经存在有效的 L3 watchdog。

如果已经存在：

优先复用。

不要建立第二套互相冲突的 watchdog。

必须验证它当前真实存活，并且知道：

- 当前 Coordinator；
- 当前 STATE.md；
- 当前工件链；
- 漂移判断；
- 唤醒目标。

如果项目治理规范要求 L3 watchdog，但当前不存在或已经死亡：

按照当前规范恢复最低必要的 watchdog 能力。

watchdog 的恢复链应至少支持：

```text
检测到漂移
↓
Poke Coordinator
↓
在配置的恢复窗口内检查是否出现真实 STATE / Task Graph 变化
↓
如果恢复 → 继续普通监督
↓
如果 Coordinator 无响应 / 状态不再变化
↓
Poke Governance Supervisor
↓
Supervisor Reconcile
↓
必要时进入 Coordinator Recovery
```

watchdog 不得因为已经发送过一次 Coordinator 唤醒，就无限向同一个失效终端重复发送而没有升级路径。

不要仅仅声称：

> “watchdog 会自动工作。”

必须有实际证据。

---

# 二十三、注意：Governance Supervisor 不等于 L3 watchdog

即使存在治理监督者 Agent：

也不能因此自动认为：

> L3 watchdog 已经存在。

因为 Governance Supervisor 本身也可能受到：

- 回合结束；
- Session 停止；
- Context 重启；
- 宿主生命周期；

影响。

因此：

```text
Governance Supervisor
=
智能治理层

L3 watchdog
=
机械唤醒层
```

两者职责不同。

# 二十五、Coordinator 最终业务 Gate

A V1.1 与 B V1.1 完成以后，由 Coordinator 执行：

> **Final Business Gate**

此 Gate 负责判断业务成果是否满足本次 Task Contract。

检查：

### A V1.1

- 是否完整；
- 是否真正反推当前成熟项目；
- 是否含可直接给 Planner 的完整 Day 1 Prompt；
- 是否使用普通用户语言；
- 是否体现 Planner 先澄清再开发；
- 是否包含压力测试；
- 是否包含产品边界和验收标准；
- 是否吸收 B 的关键发现。

### B V1.1

- 是否完整；
- 是否分析最初 vs 当前差距；
- 是否解释为什么；
- 是否解释不说会怎样；
- 是否给出下次怎么表达；
- 是否建立用户 / Planner / Developer 责任边界；
- 是否包含小白需求表达框架；
- 是否包含项目开始前检查表；
- 是否吸收 A 的关键发现。

Coordinator 的 Final Business Gate 通过以后：

不得立刻把 Run 标记为 CONVERGED。

应进入：

> **Run = VALIDATING / CONVERGENCE_CANDIDATE**

并解锁 Governance Supervisor 的最终治理复核。

---

# 二十五-A、Governance Reconciliation Gate

Governance Supervisor 对候选收敛状态进行最终治理复核。

重点检查：

1. Business Completion 是否有真实 Artifact 证据；
2. Lifecycle Completion 是否真实 settle；
3. 是否存在 FALSE_COMPLETION；
4. 是否存在 ORPHANED_COMPLETION；
5. 是否存在 unresolved question / escalation；
6. 是否还有 READY Task 未派发；
7. 是否还有必要 Active Worker；
8. STATE.md 是否与真实 Business / Control-plane 状态一致；
9. 本次 Run 是否仍遵守锁定的 Governance Spec，或已完成显式 Migration；
10. Coordinator 的 Final Business Gate 是否有证据而非仅自然语言声称。

Governance Supervisor 返回：

- `PASS`
- `NEEDS_RECONCILIATION`
- `NEEDS_FIX`
- `BLOCKED`

只有：

> **Governance Reconciliation = PASS**

才允许整个 Run 进入最终 CONVERGED。

如果不是 PASS：

定位责任节点，执行最低必要纠偏 / reconciliation / recovery，然后重新进入必要验证路径。

---

# 二十六、最终 Completion Reconciliation

在宣布完成前：

必须同时确认：

## Business Completion

- A V1.0 存在；
- B V1.0 存在；
- A V1.1 存在；
- B V1.1 存在；
- 内容满足 Acceptance Criteria；
- A/B 第一阶段真实独立；
- 第二阶段真实发生交叉审查。

以及：

## Lifecycle Completion

- 必要 Task 已终态；
- 必要 Dispatch 已 settle；
- completion 已对账；
- 无 orphaned completion；
- 无 unresolved question；
- 无 unresolved escalation；
- 无必要 Active Worker；
- Coordinator Final Business Gate 已完成；
- Governance Reconciliation Gate = PASS。

只有：

```text
BUSINESS COMPLETION
+
LIFECYCLE COMPLETION
+
GOVERNANCE RECONCILIATION = PASS
```

三者同时成立：

才能：

> CONVERGED

必须执行当前《Orca 通用编排者持续推进协议》的回合结束检查。

至少保证：

1. 当前真实工件已清扫；
2. STATE.md 已更新；
3. 下一动作明确；

如果其中存在未处理缺口：

不得因为刚刚向用户汇报了一次状态就停止推进。

# 核心原则

> Worker 负责产出内容。

> Coordinator 负责持续推动 Task Graph。

> Governance Supervisor 负责确认 Coordinator 和 Orca 生命周期真的在推动 Task Graph。

> STATE.md + 文件工件负责留下可恢复的客观状态。

> 正常运行时 Coordinator 是 STATE.md 唯一 Writer；Supervisor 只有在 Coordinator Recovery 时才接管。

> Artifact 是 Business / Work State 的主要事实来源；Orca Run / Task / Dispatch / lifecycle 是 Control-plane State 的主要事实来源。

> 外部 watchdog 负责在 Agent 回合失活时重新触发推进，并在 Coordinator 无响应时升级唤醒 Governance Supervisor。

> WORK COMPLETED 不自动等于 LIFECYCLE COMPLETED。

> Control Plane Failure 不等于 Work Failure。

> Repair Lifecycle, Preserve Work。

> Coordinator 只能提出收敛候选；最终 CONVERGED 必须经过 Governance Reconciliation PASS。

> 用户不是 watchdog。

整个 Run 在真正 CONVERGED 以前，不得无理由停止推进。
