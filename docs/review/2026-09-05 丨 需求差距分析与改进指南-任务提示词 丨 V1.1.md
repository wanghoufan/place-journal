# 项目需求复盘：分析我最开始的要求与当前产品之间到底差在哪里

你本轮不是继续开发项目。

你的任务是完整复盘当前项目，并从“编程小白如何更好地向 Agent 表达产品需求”的角度，分析：

> 为什么我最开始觉得自己已经把需求说清楚了，但是项目真正做出来以后，却不断发现还缺东西、哪里不对，需要反复返工？

最终请把这次经验整理成一份以后可以长期保存和复用的 Markdown 文档。

---

# 一、你的角色

你是：

**项目复盘分析师 + 产品需求老师 + Agent 协作改进顾问。**

你本轮：

- 不继续开发；
- 不修改业务代码；
- 不新增功能；
- 不负责重新设计当前产品；
- 不把重点放在代码质量。

你的核心任务是：

> 通过这个真实项目，教会一个完全不懂编程的人，以后怎样更早把自己真正想要的产品讲清楚。

# 二、我的背景

我是编程小白。

所以不要默认我知道：

- PRD；
- MVP；
- 数据模型；
- Schema；
- CRUD；
- API；
- 状态管理；
- 边界条件；
- 异常处理；
- 用户旅程；
- 信息架构；
- 响应式设计；
- 验收标准；
- 非功能需求。

如果必须使用专业词，请立刻翻译成人话。

例如：

不要只告诉我：

> 你没有定义 CRUD。

应该告诉我：

> CRUD 可以简单理解成：一条数据以后能不能新增、查看、修改和删除。你最开始可能只想到“我要保存一条记录”，但是没提前想到“保存错了怎么办”“以后想修改怎么办”“不要了怎么删除”，这些东西就只能开发到后面再补。

我要的是这种解释方式。

# 五、每一个重要差距都必须回答 7 个问题

针对每一个重要差距，请严格按照以下结构分析。

## 1. 我最开始是怎么说的？

引用或概括我当时真实表达。

## 2. 当前最终变成了什么？

说明现在实际实现的状态。

## 3. 中间到底差在哪里？

用一句非常简单的话告诉我。

## 4. 为什么这一点应该尽量提前想？

使用真实场景解释。

## 5. 如果一开始没有说，会发生什么？

例如：

- 页面返工；
- 数据返工；
- 功能重新拆；
- Agent 自己脑补错误；
- UI 反复修改；
- 后面加功能困难；
- 项目方向不断偏移。

必须结合本项目真实情况。

## 6. 下一次我应该怎么说？

给我一段：

> 普通人直接说出口就可以使用的话。

不要要求我使用专业术语。

## 7. 提前说清楚以后有什么好处？

例如：

- 少返工；
- 页面一开始就比较合理；
- 数据设计更完整；
- Agent 更不容易自己猜；
- 验收更容易；
- 开发顺序更合理。

# 六、判断哪些事情到底应该由谁负责

不要把所有需求遗漏都归因于我。

请分成三类。

## 第一类：普通用户自己应该提前想清楚

例如：

- 我为什么要做这个工具？
- 我平时什么时候会使用？
- 我最常做什么？
- 什么操作让我觉得麻烦？
- 我希望最后获得什么结果？

这类不需要懂编程。

属于我应该逐渐学会表达的事情。

## 第二类：我可能不知道，但计划者应该主动问

例如：

我可能根本不知道什么叫：

> 空状态。

但是一个优秀计划者应该主动问我：

> 第一次打开软件，里面一条数据都没有的时候，你希望看到什么？

请根据本项目真实情况找出：

> 哪些事情我作为小白不知道很正常，但计划者本来就应该主动追问。

## 第三类：属于技术人员负责，我不需要学会以后才能开发

例如：

- 数据库怎样建表；
- API 怎么设计；
- React 怎么拆组件；
- 用什么状态管理；
- 用哪种缓存方案；
- 代码目录怎样组织。

明确告诉我：

> 哪些事情以后不需要我操心。

我只需要说清楚最终想达到什么效果。

# 七、分析过去返工的真正来源

把返工至少分成三类。

## A. 本来可以提前避免

如果第一天沟通得更好，理论上可以明显减少。

## B. 正常产品迭代

即使需求已经比较完整，也可能只有真正看到界面、真正使用之后才发现。

这种返工不应该认为是失败。

## C. Agent / 计划者本来应该主动发现

如果一个优秀的计划者本应该追问，但是没有问，请明确指出。

不要为了迁就用户而把责任全部归给用户。

# 八、给我建立「编程小白需求表达框架」

请根据本项目的真实经验，总结：

> 以后开发任何类似小工具，在第一天我至少应该告诉计划者什么？

不要给我几十个专业问题。

压缩成大约：

**8～12 个最重要的普通人问题。**

例如：

- 我为什么要做它？
- 我平时什么时候打开它？
- 一次完整使用过程是什么？
- 我要保存什么？
- 数据多以后怎么找？
- 哪些事情我每天都做？
- 哪些操作绝对不能麻烦？
- 手机还是电脑用得更多？

具体问题请根据项目真实经验重新设计。

# 九、每一个问题都必须告诉我“为什么”

对于上面的 8～12 个问题，每一个都按照下面格式说明。

## 我应该提前告诉 Agent 什么？

具体问题。

## 为什么要问这个？

用小白能理解的话解释。

## 不说会怎样？

告诉我常见返工后果。

## 我应该怎么表达？

提供一段普通人的自然语言模板。

例如：

> 我每天可能新增 3～5 条记录，过几个月以后会有几百条，所以我希望以后可以很快找到以前保存的东西，不想只能一条条往下翻。

不要写成：

> 系统必须具备高扩展性的检索架构。
